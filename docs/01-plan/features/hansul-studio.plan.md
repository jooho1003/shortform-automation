# 한술툰 주제·콘티 작업실 Plan

작성: 2026-10-01. 사용자 요청의 구현 범위를 기준으로 bkit Plan → Design → Do → Check/Act → Report 진행.

## Executive Summary

| 관점 | 내용 |
|---|---|
| 문제 | 로컬 인스타툰에서 시리즈의 주제·콘티 생성과 수정 반복을 할 수 없다. |
| 해결 | 한술툰 작업실과 회차별 검토 화면을 기존 인스타툰 편집기에 연결한다. |
| 기능 효과 | 주제·콘티 각각 자동/수동 작성, 직접 수정, 피드백 재생성, 버전 복원, 승인 후 편집. |
| 핵심 가치 | 사용자가 결과를 확인하고 고친 내용이 다음 생성과 회차에 유지된다. |

## 1. 개요

관련: ../바이브코딩/한술툰/기획/한술툰-설계.md, 첫사연-연애-도시락-콘티.md, 기존 lib/carousel.ts 및 lib/llm.ts.

## 2. 범위

한술툰 시리즈 진입 카드, 다음 화 생성, 회차 전환, 주제/콘티 개별 자동·수동 모드, 주제·3화 흐름·장별 구도/대사/감정/캡션 편집, 피드백 재생성, 버전 목록/복원, 승인 후 기존 컷 편집기로 전달. 최초 진입에 기존 도시락 1화 초안을 가져온다.
이미지 생성·렌더·인스타 게시 자동화는 이번 요청의 텍스트 작업실 범위에서 제외한다.

## 3. 요구사항

- FR01: /instatoon에서 한술툰으로 이동한다.
- FR02: 다음 회차의 사연·파트를 구분하고 3화의 맥락을 생성에 전달한다.
- FR03: 주제와 콘티를 각각 자동 생성하거나 수동 입력한다.
- FR04: 화면에서 직접 고친 현재 내용과 추가 수정 요청을 함께 재생성에 전달한다.
- FR05: 저장/생성/복원 이력을 보존하고, 실패하면 입력 초안을 유지한다.
- FR06: 승인된 콘티를 기존 InstatoonEditor에서 편집할 수 있다.
- FR07: 남자 라쿤/여자 친칠라, 05 손그림, 담백한 표정, 3화 갈등→고구마→사이다 규칙을 적용한다.
- NFR: 오래된 탭의 저장 충돌은 409. 중복 요청 방지. 생성 중 상태 표시. 모바일·키보드 조작.

## 4. 완료 기준

핵심 상태 전이/검증/프롬프트 테스트, 타입 검사, 로컬 API 및 Aside UI 확인. 생성은 실제 로컬 CLI 연결로 확인하고 결과/제한을 기록한다.

## 5. 위험 대응

버전 스냅샷과 revision 조건부 저장, 파일 잠금 및 원자적 교체. 생성 전 현재 편집본을 먼저 보관하고 생성 실패도 정상적인 초안 상태로 남긴다. 승인 시 별도 컷 프로젝트를 만들어 기존 작화를 덮어쓰지 않는다.

## 6. 영향 분석

인스타툰 목록 페이지만 기존 코드 수정. 신규 작업실 모듈/라우트 추가. 카드뉴스·블로그·릴스 데이터 모델은 변경하지 않음. 기존 carousel/llm 저장·호출 API 재사용.

# 원격 아카이브 뷰어

만든 편 영상·상세페이지·이미지·릴스기획 자료를 밖에서 보는 페이지다.

## 왜 이 구조인가

본인 작업물 보관이므로 **버킷을 공개하지 않는다.** URL만 알면 보이는 구조는 미완성 시안과
클라이언트 자료가 섞이는 이 폴더에 맞지 않는다.

    로컬 저장소 ──(archive publish)──> R2 (비공개)
                                        │
                                   R2 바인딩
                                        │
    브라우저 ──(Cloudflare Access 인증)──> Pages 함수 ──> 객체

- 파일은 R2에 있고 공개 접근은 꺼 둔다.
- `viewer/functions/r2/[[path]].js` 가 바인딩으로 직접 읽어 내려 준다. Range를 처리하므로
  영상 탐색(seek)이 된다.
- 인증은 **Cloudflare Access** 가 앞단에서 맡는다. 뷰어 코드에는 인증 로직이 없다.

생성 파이프라인(Python·ffmpeg·codex·fal)은 계속 로컬에서 돈다. 웹 콘솔은 파일시스템과
자식 프로세스에 묶여 있어 서버리스에 올릴 수 없다.

## 키 규칙

R2 키는 `archive/` + 저장소 상대 경로다.

    archive/index.json                                   목록
    archive/2026-09-11/B-01-.../04-영상/final.mp4        편 영상
    archive/상세페이지/{id}/화장품-리디자인.html          상세페이지

URL에는 상대 경로만 넣고 접두사는 함수가 붙인다. 경로 세그먼트는 각각 퍼센트 인코딩하므로
한글 경로도 그대로 쓴다.

다시 발행하면 같은 키를 덮어쓴다. 아카이브는 항상 로컬과 같은 모습이 된다.

## 올리기

    cd pipeline
    .venv/Scripts/python -m shortform archive publish

- 원본 MD5를 객체 메타데이터에 적어 두고 다음 발행 때 비교한다. **바뀐 파일만 올라간다**
  (편 영상 하나가 20MB를 넘기 때문).
- 목록(`index.json`)은 항상 마지막에 올린다. 파일이 먼저 있어야 뷰어가 깨진 링크를 보지 않는다.
- 올리기 전에 대상만 보려면 `--dry-run`.
- R2 없이 목록만 보려면 `.venv/Scripts/python -m shortform archive list`.

## 배포 순서 (한 번만)

### 1. R2 버킷

Cloudflare 대시보드 → R2 → Create bucket. **Public access는 켜지 않는다.**

R2 → Manage R2 API Tokens → Create API Token
- 권한 `Object Read & Write`, 대상을 그 버킷으로 제한
- Access Key ID / Secret Access Key는 생성 직후 한 번만 보인다

`pipeline/.env` 에 채운다:

    R2_ACCOUNT_ID=
    R2_ACCESS_KEY_ID=
    R2_SECRET_ACCESS_KEY=
    R2_BUCKET=
    R2_PUBLIC_BASE_URL=https://쓰지-않지만-형식상-필요

> `R2_PUBLIC_BASE_URL` 은 상세페이지 납품용 내보내기에서 쓴다. 아카이브 발행은 쓰지 않지만
> 설정 검증이 다섯 개를 모두 요구하므로 비워 두지 않는다.

확인:

    .venv/Scripts/python -c "from shortform import r2; print(r2.config().bucket)"

### 2. Pages 프로젝트

`viewer/wrangler.toml` 의 `bucket_name = "CHANGE_ME"` 를 실제 버킷 이름으로 바꾼다.

Cloudflare 대시보드 → Workers & Pages → Create → Pages → 저장소 연결
- 빌드 명령: 없음
- 출력 디렉터리: `public`
- 루트 디렉터리: `viewer`

배포 후 Settings → Bindings → R2 bucket 에 `ARCHIVE` → 버킷을 연결한다
(`wrangler.toml` 에 적어 두었어도 대시보드에서 한 번 확인한다).

### 3. 접근 제한

Zero Trust → Access → Applications → Add an application → Self-hosted
- 도메인: Pages 프로젝트 주소
- 정책: Allow → Emails → 본인 이메일

이 단계를 건너뛰면 **주소를 아는 누구나 아카이브 전체를 본다.** 50명까지 무료다.

## 확인

1. `archive publish` 실행 → `올림 N개` 출력
2. Pages 주소 접속 → Access 로그인 화면
3. 로그인 후 목록이 뜨고 썸네일을 누르면 영상이 재생된다

목록이 안 뜨면 `/r2/index.json` 을 직접 열어 본다. 404면 아직 발행하지 않은 것이고,
500이면 R2 바인딩 이름이 `ARCHIVE` 인지 확인한다.

## 로컬에서 미리 보기

    cd viewer
    npx wrangler pages dev --port 8788 --local

로컬 R2는 비어 있으므로 객체를 직접 넣어야 한다:

    npx wrangler r2 object put "<버킷>/archive/index.json" --file <경로> --local

> 로컬 모드의 `r2 object put` 은 한글 키를 퍼센트 인코딩해 저장한다(CLI 특성).
> 실제 발행은 boto3라 원본 키를 쓰므로 이 차이는 로컬에서만 보인다. 한글 경로를 로컬로
> 확인하려면 ASCII 키로 바꿔 넣는다.

# 상세페이지 결과 샘플 테스트

2026-09-12. 앞선 검증은 의뢰서 CRUD와 텍스트 레이아웃까지였으며 완성 디자인 생성 테스트가 아니었다. 이번에는 가상 제품 의뢰서를 실제 HTML 상세페이지 레이아웃으로 렌더링한다.

## 결과

- 가상 브랜드: ONGI / 온기
- 제품: 아이보리 머그. 실제 상품이 아닌 디자인 샘플
- 의뢰서: `http://localhost:3123/detail-pages/90a6d633-6baf-4473-8a70-80bd6822a9de`
- 결과: `http://localhost:3123/detail-pages/90a6d633-6baf-4473-8a70-80bd6822a9de/preview`
- 저장 파일: `상세페이지/90a6d633-6baf-4473-8a70-80bd6822a9de/프로젝트.json`
- 이미지: `pipeline/web/public/detail-samples/ongi-mug.png` (1536×1024)

첫 화면 → 색감과 여백 → 형태 디테일 → 일상 장면 → 구매 전 확인사항으로 구성한다. 크림·올리브 톤, 넓은 여백, 큰 제목을 사용한다. 가격·용량·인증·후기는 임의로 만들지 않았다. 검수 상태는 테스트용 검수 중이며 실제 납품 완료가 아니다.

저장된 제목·섹션 카피가 결과 페이지에 반영된다. 편집 화면의 '상세페이지 결과 보기'로 이동한다. 저장하지 않은 편집은 결과에 반영되지 않는다.

## 구현 범위

이번 테스트에서 에이전트가 카피를 작성하고 built-in imagegen으로 대표 이미지를 만든 뒤 프로젝트에 연결했다. 의뢰서 제출만으로 AI가 제품 이미지를 자동 생성하는 파이프라인은 아니다. 이미지 여러 장을 자동 생성하거나 제품별로 자동 검수하지 않는다. 다른 의뢰서는 저장된 텍스트 레이아웃을 렌더링하며 샘플 머그 이미지를 대신 사용하지 않는다.

동일 이미지의 확대 부분은 새로운 실물 사진이 아니다. 실제 의뢰에는 고객 제품 사진·규격·구매 및 배송 정보를 받아 교체해야 한다.

## 이미지 제작 기록

도구: built-in `image_gen` (CLI/API fallback 미사용). 원본은 Codex 생성 이미지 폴더에 보존하고 프로젝트 public 폴더로 복사했다.

## 검증 기록

API 회귀 테스트 3개(13개 검증 항목) 통과. 최종 화면·레이아웃·빌드 결과는 아래에 추가 기록한다.

- 최종 TypeScript 검사와 `next build` 통과. 기존 동적 파일 추적 경고 5개는 유지된다.
- 데스크톱에서 제목·카피 렌더와 이미지 3곳의 로딩 확인. 같은 대표 이미지를 재사용하며 별도 촬영 3장으로 주장하지 않는다.
- 모바일 viewport 390px에서 실제 문서 폭/스크롤 폭 모두 375px로 가로 넘침 없음, 이미지 로딩 정상. 첫 화면을 육안 확인했고 검사 후 viewport를 원복했다.
- `pipeline/web/tests/export-detail-sample.py` 실행 통과. 저장된 섹션 제목 5개, 이미지 3개, 이미지 내장, 실행 스크립트 없는 결과 HTML을 검사한다.
- 단독 결과: `상세페이지/90a6d633-6baf-4473-8a70-80bd6822a9de/결과.html`. 이미지·스타일을 포함해 서버 없이 열 수 있다. 편집으로 돌아가는 링크는 로컬 콘솔이 실행 중이어야 한다.
- 샘플 프로젝트는 사용자가 결과를 볼 수 있도록 보존했다. 이미지가 자동으로 제작되는 서버 기능이나 실제 구매·결제·판매 성과는 테스트하지 않았다.

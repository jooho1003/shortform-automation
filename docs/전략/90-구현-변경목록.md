기준: `pipeline/` 현재 코드 (B-01 렌더까지 성공한 상태)

현재 코드는 **TTS 내레이션 중심 `브리핑 포커스`만** 돌린다. B안 주력 포맷(원음 중심

## 1단계 — 피드 카드 한 편을 만들 수 있게

### 1.1 TTS를 선택 입력으로
`shortform/steps/assets.py`

지금은 문장마다 edge-tts를 돌려 그 길이로 타임라인을 만든다. 원음 중심에서는
**클립 구간 길이가 타임라인의 기준**이다. TTS는 있으면 얹고 없으면 건너뛴다.

- 타임라인 기준을 TTS 합계 → 클립 구간 합계로 바꾼다
- `plan.lines`에 TTS 문장이 없으면 합성을 건너뛴다
- `narration.mp3`가 없을 때도 뒤 단계가 도는지 확인한다 (지금은 `Audio src`가 빈 문자열이면 렌더가 건너뛰긴 한다)

### 1.2 원본 오디오 유지
`shortform/steps/assets.py` `_to_9x16()`

지금은 `-an`으로 오디오를 **버린다**. 원음이 콘텐츠인 포맷에서는 치명적이다.

- 클립 오디오를 살린다
- 타임라인에 클립별 오디오 경로를 기록한다
- BGM 덕킹: 대사 구간에서 BGM을 낮춘다 (ffmpeg `sidechaincompress`)

### 1.3 피드 카드 컴포지션 — **컴포넌트는 있음, 연결만 남음**
`remotion/src/FeedCard.tsx` (290줄, 다른 세션이 2026-09-08 작성)

- 제목 2줄 / 클립 / 댓글 밴드 / 채널 크레딧 구현돼 있다. `template.ts`로 테마 해석.
- **남은 것**: `Root.tsx`에 컴포지션 등록(현재 `Short`만 있음), `render.py`가 타임라인에
  `template_id`를 넣어 넘기기.
- 규격은 `11-템플릿-규격.md`. 실물과 대조는 아직 안 했다.

### 1.4 템플릿 절 파싱 — **완료 (다른 세션)**
`shortform/planfile.py`, `shortform/templates.py`, `config/templates.yaml`

- 남은 것: 강조 자막 표(구간, 문구, 시각) 파싱, 채널 크레딧용 소스 채널명 연결.

### 1.5 길이 검사 — **규칙은 있음, 값이 충돌**
`shortform/templates.py`가 `templates.yaml`의 `duration`·`enforce_duration`을 읽는다.

- 현재 값: 피드 카드 15~30초 **강제**, 브리핑 포커스 35~60초 지침. 사용자 운영전략과 일치.
- `11-템플릿-규격.md`는 하이타치 실측을 근거로 35~75초 **경고**를 제안한다. **사용자 결정 필요.**
- 어느 쪽이든 `render.py`가 최종 타임라인 길이로 검사하도록 연결해야 한다(지금은 TTS 합계 기준).

- 피드 카드 두 종은 최종 타임라인이 35~75초를 벗어나면 경고한다 (하이타치 실측 40~75초)
- `브리핑 포커스`는 35~60초를 경고만 하고 진행한다

## 2단계 — 주간 사이클

### 2.0 조사 단계 — **완료 (2026-09-09)**

`shortform/steps/research.py`. 소스 풀의 롱폼 조회수 상위와 벤치마크 숏폼 성과를 모아
`숏폼/YYYY-MM-DD/00-조사리포트.md`를 만든다. `plan`이 이 리포트를 요구한다.

### 2.1 새 단계 `segments` — **완료 (2026-09-10)**
`shortform/steps/segments.py` (신규)

```
python -m shortform segments --source <유튜브 URL 또는 ID> --date YYYY-MM-DD
```

**가장 강한 신호는 자막의 `[웃음]` 마커였다.** 유튜브 ASR이 직접 붙이는 표시라
음량 추정보다 정확하다. 36분 영상에서 92개가 나왔다. 이걸 1순위 봉우리로 쓰고
음량 봉우리로 보충한다.

점수 = 웃음×4.0 + 음량×1.0 + 정적×0.8 + 물음표느낌표×1.0 + 감탄사×1.5 + 숫자×0.5 + 밀도×1.0
가중치는 근거 있는 값이 아니라 시작값이다. 결과를 보고 조정한다.

구현하며 잡은 함정 넷:

1. **음량 임계값은 백분위로 잡아야 한다.** 방송 오디오는 압축돼 위쪽 여유가 7dB뿐인데
   무음 구간(-69dB)이 표준편차를 부풀린다. `median+1.1*sd`가 99백분위보다 높아
   21,612개 중 2개만 통과했다. 상위 10% 백분위로 바꿨다.
2. **봉우리는 강한 것부터 집어야 한다.** 시간순으로 집으면 약한 봉우리가 자리를 차지해
   40초 안의 더 강한 봉우리가 밀려난다.
3. **유튜브 자동 자막은 2줄 롤링이다.** 각 큐가 "이전 줄 + 새 줄"을 담아서 그대로
   이어붙이면 말밀도가 초당 40자(실제는 8~10자)로 뻥튀기된다. 각 큐의 마지막
   비어 있지 않은 줄만 새 내용이다. HTML 엔티티(`&gt;`)도 디코딩해야 한다.
4. **원격 스트림에 seek 하면 안 된다.** 36분 영상 중반 한 지점에 120초가 넘게 걸리고
   20개 중 1개만 성공했다. 360p를 통째로 받아 로컬에서 뽑으면 즉시 끝나고 캐시된다.

출력: `pipeline/data/segments/<video_id>.json` +
`숏폼/YYYY-MM-DD/00-구간후보-<video_id>.png` (시각·점수·신호 내역이 찍힌 컨택트시트)

**남은 약점**: 롱샷이 섞여 들어온다. 숏폼은 인물 클로즈업이 강한데 기계가 구분하지
못한다. 화면비가 다른 삽입 화면(자료화면·폰 화면)도 그대로 잡힌다. 사람이 시트를
보고 거르는 구조라 치명적이진 않다.

## 알려진 제약

- **어절 자막 타이밍은 추정값이다.** edge-tts 7.2.8은 `WordBoundary`를 주지 않는다
  (한국어·영어 모두 확인). 문장 구간만 정확하고 그 안은 글자 수 비례 배분이다.
  피드 카드는 강조 자막을 지정 시각에 띄우므로 이 문제를 안 겪는다.
- **Pexels는 Cloudflare 뒤에 있다.** `Python-urllib` User-Agent는 1010으로 막힌다.
  브라우저 UA를 붙여야 한다 (`shortform/__init__.py`의 `USER_AGENT`).
- **한글 경로에서 `pip install -e .`가 파이썬 기동을 깬다.** `.pth`를 cp949로 읽다
  죽는다. editable 설치를 쓰지 않고 `pipeline/`에서 직접 실행한다.

# 3D 에셋과 3D 영상 제작 절차

2026-09-29. interactive-web 레포의 3D 제작 방식(이미지 → Tripo → GLB)에 Blender 렌더를 붙여 숏폼용으로 정리했다. 3D 물체·캐릭터가 들어가는 영상이나 이미지를 만들 때 이 순서를 따른다. 파이프라인 단계와 웹 콘솔에는 아직 연결하지 않았다.

```
2D 이미지(codex) → Tripo v3로 GLB 생성 → Blender 헤드리스 렌더(투명 PNG 시퀀스) → ffmpeg → Remotion 합성 / 정지 이미지
```

## 1. 입력 이미지

3D 품질은 입력 이미지에서 결정된다. Tripo 결과물은 부분 수정이 어렵다("지붕만 더 뾰족하게" 같은 수정 불가). 스타일 통일과 형태 수정은 모두 이미지 단계에서 하고 다시 생성한다.

- 3D로 만들 물체는 한 장에 하나. 단색 배경에 물체 전체가 보이게 한다. 이미지는 `config/images.yaml`의 codex(gpt-image-2.5)로 만든다.
- 메인 캐릭터는 단독 한 장으로 만든다. 그리드에 넣지 않는다. 정면·좌·우·뒤 4장을 따로 만들면 Tripo 멀티뷰 입력(최대 4장, 각도 고정)으로 쓸 수 있다.
- 소품이 여러 개면 기준 장면 한 장에서 4×4 그리드 시트를 만들고 16장으로 잘라 각각 변환한다.

  ```
  [기준 장면 첨부]
  이 이미지에 있는 사람을 제외한 오브젝트들을 4×4 그리드 안에 하나씩 나눠서 넣어줘.
  각 칸은 오브젝트 하나, 배경은 단색, 같은 조명과 같은 재질 스타일로.
  ```

- 배경 전체를 한 번에 3D로 보내면 깨진다. 3등분하고, 그래도 깨지면 더 잘게 나눈다.
- interactive-web 강연자는 캐릭터를 먼저 만든 뒤 어울리는 배경을 요청하고, 캐릭터를 뺀 다음 바닥·왼쪽·뒷면으로 나누는 순서를 쓴다. 커뮤니티에서 검증된 방식은 아니므로 소규모로 먼저 시험한다.

## 2. Tripo로 GLB 만들기

- Tripo를 쓰는 이유는 로우폴리를 가장 잘 뽑고, 리깅과 애니메이션까지 API로 처리되기 때문이다. Meshy는 2안이다.
- 오브젝트 16개는 image-to-model 태스크 16개를 병렬로 보낸다(H 시리즈 동시 실행 기본 한도 10개). 멀티뷰(4장)는 캐릭터를 단독으로 변환할 때만 쓴다.
- 키는 `pipeline/.env`의 `TRIPO_API_KEY`에 있다(`.env`는 gitignore 대상, interactive-web/.env와 같은 키). 2026-09-29에 v2·v3 잔액 조회로 키가 유효한 것을 확인했다. 다만 API 잔액이 0크레딧이라 생성하려면 먼저 충전해야 한다.
- 처음에는 오브젝트 1개로 생성부터 렌더 검수까지 한 번 돌려 품질을 확인한다.

### API v3 요약

2026-09-29에 공식 문서(developers.tripo3d.ai)를 읽고 정리했다. 잔액 조회 말고는 아직 실제로 호출해 보지 않았다. v2(`https://api.tripo3d.ai/v2/openapi/`)는 2026-10-01부터 유지보수가 끝나고 2026-11-01에 폐지되므로 v3만 쓴다. 공식 Python SDK(`tripo3d`)는 v2 기반이라 쓰지 않고 `requests`로 직접 호출한다.

- 기본 주소는 `https://openapi.tripo3d.ai/v3`, 인증은 `Authorization: Bearer <키>`다.
- 응답은 성공하면 `{"code":0,"data":{...}}`다. 실패하면 `code`가 0이 아니고 `message`가 붙는다. 크레딧 부족은 2010, 요청 과다는 HTTP 429(코드 1007·2000)다.

| 단계 | 요청 | 결과 |
|---|---|---|
| 잔액 | `GET /account/balance` | `data.balance`, `data.frozen` (소수, float로 읽음) |
| 이미지 업로드 | `POST /files` multipart `file` (PNG·JPEG, 20MB 이하) | `data.file_token` |
| 3D 생성 | `POST /generation/image-to-model` | `data.task_id` |
| 상태 조회 | `GET /tasks/{task_id}` (1~2초 간격) | `status`: queued·running → success·failed·cancelled·banned·expired |
| 다운로드 | `data.output.model_url` GET, 인증 헤더 없이 | GLB. 서명된 임시 주소라 바로 받는다 |
| 리깅 가능 여부 | `POST /animations/rig-check` `{"input": task_id}` (무료) | `riggable`, `rig_type` |
| 리깅 | `POST /animations/rig` `{"input": 생성 task_id}` | 리깅된 모델 task |
| 동작 입히기 | `POST /animations/retarget` `{"input": 리깅 task_id, "animation": "preset:walk"}` | 애니메이션이 bake된 GLB |

생성 요청 예시:

```json
{"input": "<file_token 또는 공개 이미지 URL>", "model": "v3.1-20260211", "texture": true, "pbr": true, "smart_low_poly": true, "face_limit": 10000}
```

- `model`은 필수다. 최신은 `v3.1-20260211`이다. 문서의 다른 페이지에는 `tripo-v3.1` 같은 별칭도 있어서, 날짜가 붙은 ID를 명시한다.
- 로우폴리는 `smart_low_poly: true`로 켠다. 이때 `face_limit`은 삼각형 500~20,000개로 제한된다. `quad: true`는 FBX로만 출력되므로 GLB가 필요하면 쓰지 않는다.
- 로우폴리 전용 P 시리즈(`P1-20260311`, `P2-20260801`)도 같은 엔드포인트를 쓴다.
- 리깅이나 리타겟을 할 모델에는 `export_orientation`을 넣지 않는다.
- 리타겟 프리셋(리깅 `v2.5-20260210`, 사람형): `preset:idle|walk|run|jump|climb|dive|slash|shoot|hurt|fall|turn`. 기본 리깅 `v1.0-20240301`에서는 `preset:biped:walk` 형식을 쓰고 90개 이상 있다.
- 크레딧은 태스크를 만들 때 묶였다가 성공하면 차감되고, 실패하면 풀린다. $1 = 100크레딧이다.
  - 생성: 텍스처 없음 20, 기본 텍스처 30, 상세 텍스처 40. `smart_low_poly`는 +10이다.
  - 리깅 25, 리타겟은 동작 하나에 10.
  - 16개를 기본 텍스처와 로우폴리로 생성하면 약 640크레딧($6.4)이다. 캐릭터 하나에 리깅과 동작 2개를 붙이면 +45크레딧이다.
- GLB는 회차 폴더의 `03-소재/3d/<이름>.glb`에 둔다.
- 영상 렌더에만 쓸 GLB라면 gltf-transform·gltfpack 압축은 하지 않아도 된다. 압축은 interactive-web처럼 웹에 GLB를 올릴 때만 필요하다.

## 3. Blender 렌더

Blender 4.5.12 LTS가 `C:\Program Files\Blender Foundation\Blender 4.5\blender.exe`에 설치돼 있다. PATH에 없으므로 전체 경로로 실행한다.

```powershell
$blender = "C:\Program Files\Blender Foundation\Blender 4.5\blender.exe"
# 구도 확인 (빠름)
& $blender -b -P pipeline/scripts/blender_turntable.py -- 03-소재/3d/lamp.glb 03-소재/3d/lamp-draft 90 1080 1920 draft
# 최종
& $blender -b -P pipeline/scripts/blender_turntable.py -- 03-소재/3d/lamp.glb 03-소재/3d/lamp 90 1080 1920 final
```

`pipeline/scripts/blender_turntable.py`는 GLB 하나를 불러와 카메라를 한 바퀴 돌리고, 투명 배경 PNG(`frame_0000.png`…)로 저장한다. 카메라 거리는 모델의 바운딩 구가 세로 화면의 좁은 쪽 화각에 들어오도록 잡는다. 따라서 도는 동안 모델이 잘리지 않는다. 바운딩 박스는 첫 프레임 기준이라 멀리 이동하는 애니메이션이면 거리를 따로 조정한다.

이 PC(Intel Core Ultra 7 255H, Arc 140T 내장 GPU)의 실측 속도:

| 방식 | 1080×1920 속도 | 용도 |
|---|---|---|
| `draft` — Workbench | 12프레임에 13초(Blender 시작 시간 포함) | 구도·회전 확인 |
| `final` — Cycles CPU 32샘플 + 디노이즈 | 프레임당 약 23초 | 최종 |
| EEVEE 16샘플 | 프레임당 약 30초 | 더 느려서 쓰지 않음 |

- 3초(90프레임) 턴테이블을 `final`로 렌더하면 약 35분이 걸린다. `draft`로 전체를 먼저 확인하고, `final`은 확정본에만 쓴다.
- Cycles GPU(oneAPI)는 이 PC에서 장치로 잡히지 않는다. EEVEE 기본값(64샘플)은 540×960에서도 프레임당 25~50초가 걸렸다.
- 카메라 이동이나 여러 오브젝트 배치 같은 다른 연출이 필요하면 이 스크립트를 복사해서 고친다.

## 4. 영상과 이미지로 쓰기

```powershell
# Remotion 합성용 투명 webm (VP9 알파)
ffmpeg -framerate 30 -i out/frame_%04d.png -c:v libvpx-vp9 -pix_fmt yuva420p -b:v 0 -crf 32 turntable.webm
# 단색 배경 mp4
ffmpeg -framerate 30 -i out/frame_%04d.png -filter_complex "color=c=0x202020:s=1080x1920:r=30[bg];[bg][0:v]overlay=shortest=1,format=yuv420p" -c:v libx264 -movflags +faststart turntable.mp4
```

- Remotion(4.0.523)에서는 `<OffthreadVideo transparent>`로 투명 webm을 배경·자막 위에 합성한다.
- 정지 이미지는 프레임 수를 1로 주거나 시퀀스에서 한 장을 고른다. 썸네일, 카드뉴스, 상세페이지 이미지에 쓴다.
- 미검증 아이디어: A안에서 같은 GLB를 여러 각도로 렌더해 키프레임으로 쓰면 컷마다 물체 모양이 유지될 수 있다(fal image-to-video 입력).
- 캐릭터 일관성이 무너지면 턴테이블 영상을 video-to-video 입력으로 쓴다(interactive-web 제작 가이드 §3-2).

## 검증

- 2026-09-29, Blender 4.5.12로 테스트 GLB(원숭이 머리와 큐브)의 턴테이블을 렌더했다. 1080×1920 `draft` 12프레임과 `final` 2프레임이 정상 출력됐다. 한 바퀴 도는 동안 모델이 잘리지 않았다.
- 위치 애니메이션이 있는 GLB도 회전과 함께 애니메이션이 진행되는 것을 확인했다.
- ffmpeg 8.1.2로 mp4(h264 1080×1920)와 알파 webm(VP9, `alpha_mode=1`) 인코딩을 확인했다.
- Tripo는 키가 유효한지(v2·v3 잔액 조회)만 확인했다. 잔액이 0이라 생성, 리깅, 실제 Tripo GLB 렌더는 아직 검증하지 못했다.

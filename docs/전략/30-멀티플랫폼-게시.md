# YouTube · Instagram · TikTok 게시 자동화

2026-09-12. 이번 대상은 같은 날짜의 B-02~B-05 네 편이다.
현재 단계는 로컬 게시 준비와 연결 코드 구현이다. 실제 계정 연결·저장소·일정 설정과 첫 실게시 검증은 남아 있다.

## 연결 방식

기본 후보는 Buffer다. 기존 Python 파이프라인에서 게시 목록을 만들고, Buffer에 보내면 지정 시각의 실제 게시를 Buffer가 처리한다. 예약이 정상 접수된 뒤에는 이 PC에서 매일 작업을 실행할 필요가 없다. 단, 영상 URL은 게시 시점까지 접근 가능해야 한다.

```text
완성 MP4 + 기획안
    → 3개 플랫폼의 게시 목록
    → 계정·공개 범위·일정 설정
    → 공개 저장소의 영상 파일 확인
    → Buffer에 초안/즉시/예약 게시 요청
    → 플랫폼별 상태 확인 및 결과 기록
```

Buffer 무료 플랜은 3개 채널, 채널당 예약 대기 10건과 API 접근을 제공한다. 이번 4편을 세 플랫폼에 올리는 게시 대기는 이 범위 안이다. 별도 영상 저장소의 비용은 포함하지 않는다. [공식 요금표](https://buffer.com/pricing)

TikTok의 자체 Direct Post API는 개인·내부 계정 관리 도구에 제한이 있고 미심사 클라이언트의 공개 게시에도 제약이 있다. 따라서 이 프로젝트에서 개인용 TikTok Direct Post 앱을 먼저 만드는 방식을 기본 경로로 삼지 않았다. [TikTok 개발 지침](https://developers.tiktok.com/docs/en/content-sharing-guidelines)

## 최초 연결

1. [Buffer 계정](https://buffer.com/)에서 [Channels](https://account.buffer.com/channels)를 열고, 본인이 게시할 YouTube·Instagram·TikTok 계정을 연결한다.
2. Instagram은 Business 또는 Creator 계정이어야 자동 게시가 가능하다. Personal 계정은 알림을 받은 뒤 앱에서 게시하는 방식이다. [공식 안내](https://support.buffer.com/en-us/articles/scheduling-instagram-posts-reels-stories-and-notifications-3XA98S9Q5p)
3. Buffer Settings → API에서 개인 API 키를 만든다. `pipeline/secrets/buffer-api-key.txt`에 키 한 줄만 저장하거나 `BUFFER_API_KEY` 환경변수를 설정한다. `pipeline/secrets/`는 git 제외 대상이다. 비밀번호나 API 키를 기획안·게시목록·채팅에 넣지 않는다. [API 시작하기](https://developers.buffer.com/guides/getting-started.html)
4. 아래 `channels` 명령으로 실제 연결된 계정명과 ID를 확인한다. 영상의 출처 채널인 **요정재형은 게시할 본인 계정 ID가 아니다.**
5. MP4를 본인이 선택한 공개 HTTPS 저장소에 놓고 영상 URL을 입력한다. Buffer API는 로컬 파일을 직접 받지 않는다. Google Drive 공유 화면이나 로그인 페이지 주소는 MP4 직접 주소가 아니다. [미디어 호스팅 조건](https://developers.buffer.com/guides/hosting-media.html)

## 명령

작업 위치는 `shortform-automation/pipeline`이다.

```powershell
# 4편 × 3플랫폼 게시 목록 생성. 이미 있으면 덮어쓰지 않는다.
.venv\Scripts\python -m shortform publish prepare --date 2026-09-12 --episodes 02,03,04,05

# 연결된 계정 조회. 게시하지 않는다.
.venv\Scripts\python -m shortform publish channels

# 수정한 게시 목록 검사. 게시하지 않는다.
.venv\Scripts\python -m shortform publish check --manifest ../2026-09-12/게시목록.json

# 기본 send는 검사만 한다.
.venv\Scripts\python -m shortform publish send --manifest ../2026-09-12/게시목록.json

# 목록에 지정한 계정·내용·방식으로 실제 전송한다.
.venv\Scripts\python -m shortform publish send --manifest ../2026-09-12/게시목록.json --execute

# 로컬 접수 기록 / 원격 상태 재조회
.venv\Scripts\python -m shortform publish status --manifest ../2026-09-12/게시목록.json
.venv\Scripts\python -m shortform publish sync --manifest ../2026-09-12/게시목록.json
```

## 게시 목록에서 정할 값

| 필드 | 의미 |
|---|---|
| `channel_id` | `channels` 조회에서 확인한 본인 계정의 Buffer ID |
| `video_url` | 해당 완성 MP4와 내용이 동일한 공개 HTTPS 직접 주소 |
| `mode` | `draft`는 Buffer 초안, `now`는 즉시 게시, `schedule`은 예약 게시 |
| `due_at` | 예약 게시일 때 시간대가 포함된 미래 시각. 예: `2026-09-20T19:00:00+09:00` |
| `privacy` | YouTube 공개 범위 `private` / `unlisted` / `public`. 기존 기획안의 `unlisted`를 자동으로 `public`으로 바꾸지 않는다 |
| `title`, `text` | 플랫폼별 제목과 설명. 사용자 수정 가능 |

처음 생성한 목록의 `mode`는 `pending`이다. 이는 로컬에서 일정이 아직 정해지지 않았다는 뜻이며 Buffer 초안을 이미 만들었다는 뜻이 아니다. Instagram과 TikTok은 이 도구에서 임의로 비공개 범위를 정하지 않는다. 먼저 확인하려면 세 플랫폼 모두 `draft`로 보내 Buffer에서 확인한다.

## 중복과 실패 처리

- 로컬 파일의 SHA256, 플랫폼, 게시 계정 ID 조합을 `pipeline/data/publishing.sqlite3`에 기록한다. 다른 게시목록으로 다시 실행해도 같은 조합을 자동 재전송하지 않는다.
- 게시 전 영상의 실제 바이트가 검토한 로컬 MP4와 같은지 확인한다. 영상 호스팅 URL로는 Buffer API 키를 전송하지 않는다.
- 요청 전에 전송 중 상태를 기록한다. 응답을 잃거나 프로세스가 중단되어도 다시 실행하면서 같은 영상을 새로 올리지 않는다.
- 원격 게시 ID를 받은 경우 `sync`로 상태만 조회한다. `scheduled`나 `draft`는 접수 상태이며 `sent`와 구분한다.
- 게시 ID 없이 `unknown` 또는 `sending`으로 남으면 Buffer 대시보드에서 실제 생성 여부를 먼저 확인한다. 자동 초기화·자동 재시도 명령은 두지 않았다.
- 예약된 날짜가 지났다고 자동으로 즉시 게시로 바꾸지 않는다.

기존 `run --only upload`는 YouTube 직접 API 경로이고 새로운 `publish`의 중복 기록과 공유되지 않는다. 같은 편은 새 `publish` 경로로 통일한다. 기존 웹 콘솔의 업로드 버튼도 아직 YouTube 직접 업로드를 실행하므로, 3플랫폼 게시에는 위 CLI를 사용한다.

## 구현과 확인 범위

- Buffer 공식 GraphQL API의 계정 조회·게시 생성·상태 조회를 사용한다.
- 플랫폼별 제목·설명·영상 주소를 JSON 변수로 전송한다.
- 공통 렌더·기존 업로드 화면은 유지한다. 현재 새 기능의 조작 경로는 CLI다.
- 테스트는 로컬 준비·검증·중복 방지·통신 실패를 가짜 API로 검증한다. 실제 계정 권한과 플랫폼 게시 성공은 연결 후 첫 실게시에서 확인해야 한다.
- 참고 API: [게시 예제](https://developers.buffer.com/examples/create-video-post.html), [스키마](https://developers.buffer.com/reference.html).

# 상세페이지 외주 작업실

2026-09-12. 기존 숏폼 콘솔에 추가한 로컬 제작 관리 화면이다.

## 시작하기

1. 콘솔의 **상세페이지 의뢰서** 메뉴 또는 `http://localhost:3123/detail-pages`를 연다.
2. **새 의뢰서**에서 프로젝트 이름·고객·제품을 입력한다.
3. 대상, 목적, 핵심 메시지, 브랜드 스타일을 적고 **확인된 제품 정보 / 근거 자료 / 제공 자산·사용 조건**을 분리해 입력한다. 참고 URL은 한 줄에 하나씩 적는다.
4. 기본 5개 섹션의 제목·카피·이미지 연출을 편집한다. 제품 대표컷, 사용 디테일, 개념 CGI 프리셋은 기존 연출 뒤에 추가된다.
5. 섹션별 **제작 지시문 미리보기 / 복사**로 외부 제작 도구나 작업자에게 전달할 내용을 준비한다. 확인하지 않은 수치·효능·후기는 채우지 않는다.
6. 우측 최대 375px 텍스트 레이아웃에서 현재 입력의 흐름을 확인한다. 이 화면은 생성 이미지나 완성 디자인을 렌더링하는 기능이 아니다.
7. 섹션 검수와 최종 4개 검수를 기록하고 납품 URL을 입력한다. 모든 섹션이 확인됨이고 최종 검수를 전부 체크해야 납품 완료로 저장할 수 있다.
8. **저장**으로 파일에 반영하거나 **Markdown 다운로드**로 현재 입력을 전달용 문서로 내보낸다. 다운로드에는 아직 저장하지 않은 입력도 포함된다.

기본 섹션은 첫 화면·핵심 제안 → 고객 고민·제품 역할 → 제품 특징·근거 → 사용 방법·디테일 → 구매 안내·다음 행동이다. 제목과 카피를 의뢰에 맞게 수정한다. 빈 의뢰서에 판매 수치·효능·고객 후기를 자동으로 만들어 넣지 않는다.

## 저장과 범위

- 파일: 프로젝트 루트 `상세페이지/<UUID>/프로젝트.json`. 기존 숏폼 외주 고객·월간 보드와 별도로 관리한다.
- API: `GET/POST /api/detail-pages`, `GET/PUT /api/detail-pages/<UUID>`.
- 저장 중 편집을 잠그며, 이전 버전으로 덮어쓰려 하면 409를 반환한다. 충돌 시 Markdown으로 입력을 보존한 다음 새로고침하고 다시 반영한다.
- UTF-8 JSON을 임시 파일에 쓴 뒤 원자적으로 교체한다. 동시 저장은 프로젝트별 파일 잠금으로 보호한다.
- 로컬 파일 기반의 내부 작업실이다. 고객용 공개 문의 폼, 견적·결제, 파일 업로드, 이미지 자동 생성, 완성 상세페이지 HTML/PNG 내보내기, 외부 공개 배포는 이번 범위에 포함되지 않는다.
- 납품 URL은 기록용이며, 저장 시 해당 사이트로 파일을 전송하거나 공개하지 않는다.
- 서버가 저장 도중 비정상 종료해 `.lock`이 남았다면, 실행 중인 저장 작업이 없음을 확인한 뒤 해당 프로젝트의 잠금 파일만 정리해야 한다. 자동으로 잠금을 빼앗지 않는다.

## 숏폼 연출 가이드

A 회차 → 이미지·클립 → **연출 가이드**를 펼친다. 컷을 선택한 뒤 시작 화면·끝 화면·카메라 이동·효과음을 적는다. 기존 기획안의 액션, 카메라, 렌즈, 길이, 캐릭터·의상·스타일 고정 조건을 포함하는 지시문이 만들어진다.

제품 클로즈업, 요리 손동작, 공간 이동 프리셋을 출발점으로 사용한다. 리트리버는 캐릭터 기준 앞발·비율을 유지하고 시선과 조리 도구의 접촉점을 명확히 적는다. 감정은 추상적인 이름보다 귀·눈·꼬리의 관찰 가능한 움직임으로 적는다.

**이 가이드의 입력은 브라우저 내 임시 초안이다.** 복사 후 기획안이나 제작 도구에 옮겨야 하며, 생성 설정으로 자동 저장·실행되지 않는다. 기존 선택 컷 이미지 재생성 요청과도 별개다.

검수 기준은 첫 프레임의 가독성, 자막·음성 일치, 효과음·BGM 균형, 마지막 프레임과 다음 컷의 연결이다. UI의 안내만 읽었다고 실제 영상 검수가 완료된 것으로 기록하지 않는다.

참고자료별 적용 근거와 열람 범위는 [33-크롬-제작자료-검토.md](33-크롬-제작자료-검토.md)에 기록했다.

## 검증

- 웹 TypeScript 검사.
- API 자동 검증: 생성·조회·수정, 저장 버전 충돌, 동시 저장, 입력 URL·날짜·섹션 ID, 납품 조건, 잘못된 JSON·ID·Origin.
- 실행: `cd pipeline/web` 후 `py -3 tests/detail-pages-api.py`. 테스트는 localhost 서버를 대상으로 임시 프로젝트를 만들고 정리한다.
- 화면과 빌드의 최종 확인 결과는 참고자료 검토 문서의 완료 기록에 추가한다.

# 네이버 블로그 자동화 보안 검토

작성일: 2026-09-18

## 결론

- 기본 게시 방식은 외부 계정을 건드리지 않는 `copy`다.
- `draft`는 `config/blog.yaml`의 `draft_enabled: true`, 승인 해시 일치, lint 오류 0, 잡 러너의 `confirmed`, CLI의 `--execute --confirmed`가 모두 있어야 실행된다.
- 자동 발행·예약 발행은 구현하지 않았다.
- 네이버 비밀번호는 받거나 저장하지 않는다. 사용자가 화면에 보이는 전용 Chrome에서 직접 로그인하며 프로필은 git 제외 경로인 `pipeline/secrets/naver-profile/`에만 남는다.

## 비밀값

네이버 키 5종은 `pipeline/.env` 또는 프로세스 환경에서만 읽는다. API 클라이언트는 키·HMAC 원문·응답 본문을 로그에 출력하지 않는다. 환경 점검 화면은 값이 아니라 존재 여부와 저장 위치만 보여 준다.

- `NAVER_CLIENT_ID`
- `NAVER_CLIENT_SECRET`
- `NAVER_AD_CUSTOMER_ID`
- `NAVER_AD_ACCESS_LICENSE`
- `NAVER_AD_SECRET_KEY`

`safePath.ts`는 `pipeline/secrets`, `.env*`, `.git` 접근을 계속 거부하므로 `/api/media`로 프로필·쿠키·키를 읽을 수 없다.

## 입력·출력 경계

- 블로그 프로젝트 ID는 날짜 접두사가 있는 제한된 문자만 허용한다.
- API 쓰기 요청은 같은 origin의 JSON만 받고 1MB에서 중단한다.
- 파일 저장은 프로젝트 폴더 내부의 고정 파일명만 사용하고 revision 충돌과 잠금 파일을 검사한다.
- 마크다운 변환기는 원문 HTML을 허용하지 않고 모든 텍스트를 escape한다. 링크는 계정 정보가 없는 HTTP(S), 이미지는 프로젝트 상대 경로만 허용한다.
- 미리보기는 정제된 HTML을 `sandbox=""` iframe에 넣어 부모 화면의 권한·저장소·스크립트에 접근하지 못하게 한다.

## 외부 발신·멱등성

- 네이버 에디터의 모든 필수 셀렉터가 존재하는지 확인하기 전에는 제목·본문·태그를 하나도 입력하지 않는다.
- 셀렉터가 맞지 않으면 스크린샷만 남기고 종료한다.
- 임시저장 슬롯은 `publishing.sqlite3/blog_publishing`의 `(body_sha256, blog_id)` 유일키로 선점한다.
- 입력 후 결과가 불확실하면 `unknown`으로 남기고 자동 재시도하지 않는다. `blog sync`로 사람이 확인한 결과만 반영한다.
- 하루 최대치는 설정과 무관하게 3 이하로 고정하며 기본은 1, 간격은 기본 12시간이다.

## 남은 사람 확인

네이버 에디터 DOM은 공식 계약이 아니다. `naver-editor.yaml`의 셀렉터는 의도적으로 비워 두었다. 계정 주인이 draft 사용을 명시적으로 결정한 뒤, 화면에 보이는 브라우저에서 비공개 임시저장 1건으로만 셀렉터와 붙여넣기 서식 보존을 확인해야 한다. 이 확인 전에도 copy 모드는 완전히 사용할 수 있다.

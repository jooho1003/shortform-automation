# 네이버 블로그 자동화

작성일: 2026-09-18 · 상태: **구현 완료 (draft 실계정 검증만 승인 대기)**

기존 숏폼 콘솔에 `/blog`를 추가한다. **키워드 발굴 → 개요 → 근거 조사 → 본문 → 윤문 → 이미지 → 점검 → 게시 → 순위 추적**을 한 화면에서 돌리고, 사람은 **개요 승인·원고 승인·발행 버튼** 세 곳에서만 개입한다. 글 소재는 숏폼 회차와 무관한 **블로그 전용 새 글**이다. 회차 재가공은 이번 범위가 아니다.

구현 결과: 파일 SSOT·CRUD·승인 해시·lint·안전한 미리보기, 네이버 검색/검색광고 API와 키 없는 폴백, 4단 LLM 파이프라인, Remotion 대표 이미지, copy 패키지, draft 안전장치, 순위 추적, 주간/일간 스케줄러와 `/blog` 화면을 구현했다. 자동 테스트와 프로덕션 빌드, 브라우저의 생성→편집→점검→승인→copy 패키지 흐름을 통과했다. `draft`의 실제 네이버 DOM 셀렉터와 붙여넣기 보존 확인은 외부 계정 조작이므로 계정 주인의 별도 승인 전까지 의도적으로 비워 둔다.

플랜: `.claude/plans/naver-blog-automation-2026-09-18.*` · 선례: [37-카드뉴스](../전략/37-카드뉴스-인스타툰-자동화.md)(저장소·CRUD·lint), [30-멀티플랫폼-게시](../전략/30-멀티플랫폼-게시.md)(외부 발신 규율)

## 1. 현재 구조와 설계 기준

| 확인한 현재 코드 | 설계에 반영할 사항 |
|---|---|
| SSOT는 파일. 웹에 DB·전역 인증 없음 (`pipeline/web/README.md`) | 글 하나 = `블로그/<id>/` 폴더. DB를 새로 들이지 않는다 |
| 프로젝트형 콘텐츠는 `<한글폴더>/<id>/프로젝트.json` + Node 직접 CRUD (`lib/carousel.ts`, `lib/detailProjects.ts`) | 같은 구조. `revision` 낙관적 잠금·임시파일+rename 저장은 `detailProjects.ts` 방식을 따른다 |
| LLM은 API 키 없이 `claude -p`·`codex exec` spawn (`lib/llm.ts`) | 그대로 쓴다. 근거 조사 단계만 도구 허용 옵션을 `runLlm`에 추가한다 |
| 프롬프트는 `pipeline/prompts/<도메인>/*.md` + `{{변수}}` (`lib/reels.ts`) | `pipeline/prompts/blog/`에 둔다 |
| 장기 실행은 잡 러너 + SSE, 클라이언트는 프리셋 이름만 보낸다 (`lib/runner.ts`, `lib/presets.ts`) | 네트워크·게시 작업은 전부 프리셋으로 추가. 임의 인자 금지 |
| 외부 발신은 `dangerous` + `confirmed` + 멱등 키 + `unknown` 상태 자동 재전송 금지 (`shortform/publishing.py`) | 블로그 게시기도 같은 규율. 같은 SQLite 파일에 테이블만 추가 |
| 웹에서 Python `publish`를 부르는 경로는 아직 없다 | 블로그 게시 프리셋이 첫 사례가 된다. `DANGEROUS_STEPS`와 동급으로 취급 |
| 카드뉴스는 렌더·게시가 미완성(K3·K7 `todo`) | 산출물 뽑는 패턴은 회차 파이프라인(`/api/jobs` → preset → python)을 따른다. 카드뉴스에서는 타입·CRUD·lint만 가져온다 |
| 이미지에 글자 금지, 글자는 컴포넌트가 얹는다 (`remotion/src/carousel/`) | 대표 이미지(썸네일)는 Remotion Still, 본문 이미지는 codex 생성(글자 없음) |
| 블로그·SEO·네이버 연동 흔적은 코드·문서에 없다 | 완전한 신규 도메인. 기존 파일 수정은 `Nav.tsx`·`paths.ts`·`presets.ts`·`llm.ts`·`cli.py`·`inspect.py`·`Doctor`에 한정 |

## 2. 네이버가 허용하는 것과 막은 것

설계 전체를 가르는 제약이다.

| 항목 | 사실 | 설계 결론 |
|---|---|---|
| 글쓰기 API | **2020-05-06 종료.** 기계적 대량 게시 때문에 10년 만에 닫았다 ([뉴스핌](https://www.newspim.com/news/view/20200413000737)) | 공식 게시 경로는 없다 |
| 약관 | 매크로·로봇 등 자동화된 수단의 **게시물 게재** 금지 (2018 약관 개정, [한국경제TV](https://www.wowtv.co.kr/NewsCenter/News/Read?articleId=AKR20180404169400033)) | 브라우저 자동화 게시는 약관상 회색~위반 영역이다. 기본값으로 두지 않는다 |
| 키워드 검색량 | 검색광고 API `GET /keywordstool` — 월간 검색수(PC·모바일)·경쟁정도·연관 키워드 ([naver/searchad-apidoc](https://github.com/naver/searchad-apidoc)) | 공식 경로로 자동화한다 |
| 블로그 검색 | 오픈API `v1/search/blog.json` — 상위 글 제목·요약·링크·총 문서 수 ([오픈API 목록](https://naver.github.io/naver-openapi-guide/apilist.html)) | 경쟁 분석·순위 추적에 쓴다 |
| 검색 트렌드 | 데이터랩 검색어 트렌드 API (같은 목록) | 계절성 확인용. 1차 범위에서는 선택 |
| 통계(조회수) | 공개 API 없음 **[미확인]** | 자동 수집하지 않는다. 순위만 추적 |

**결론: 자동화의 무게를 "게시"가 아니라 "게시 직전까지"에 싣는다.** 키워드·개요·조사·본문·이미지·점검은 100% 자동, 게시는 3단 모드로 나눈다(6절).

## 3. 자동화 흐름

```text
[주간] 키워드 발굴 ─→ 키워드 보드 (점수순)
                         │ 선택 또는 "이번 주 N편" 일괄
                         ▼
                 ① 개요 생성 (LLM) ──■ 게이트1: 개요 승인
                         ▼ 승인 후 자동 연쇄
   ② 근거 조사 → ③ 본문 → ④ 윤문 → ⑤ 이미지 → ⑥ 점검(lint)
                         ▼
                 ■ 게이트2: 원고 승인 (본문 sha256 고정)
                         ▼
                 ⑦ 게시 (copy | draft | publish) ── 사람이 발행
                         ▼
                 ⑧ 순위 추적 (매일)
```

| 단계 | 실행 주체 | 입력 → 출력 | 소요(추정) |
|---|---|---|---|
| 키워드 발굴 | Python `blog keywords` | `config/blog.yaml` 시드 → `pipeline/data/blog/keywords/<YYYY-Www>.json` | 1~2분 |
| 상위글 분석 | Python `blog serp` | 키워드 → `상위글.json`(상위 10개 제목·요약·작성일) | 수 초 |
| ① 개요 | claude (schema) | 키워드+상위글 → `개요.json` | ~2분 |
| ② 근거 조사 | claude (WebSearch·WebFetch 허용) | 개요의 `facts_needed` → `근거.json` | 3~6분 |
| ③ 본문 | claude | 개요+근거 → `본문.md` | ~3분 |
| ④ 윤문 | claude | `본문.md` → `본문.md`(원본은 `본문.초안.md` 보존) | ~2분 |
| ⑤ 이미지 | Remotion Still + codex | 개요의 `images[]` → `이미지/NN.jpg` | 장당 ~3분 |
| ⑥ 점검 | Node `lintBlog()` | 전체 → `점검.json` | 즉시 |
| ⑦ 게시 | Python `blog publish` | 승인된 원고 → 복사 패키지 / 임시저장 | 1~3분 |
| ⑧ 순위 | Python `blog rank` | 게시 URL+키워드 → `순위.json` 누적 | 글당 수 초 |

소요 시간은 기존 릴스 기획 실측(분석 ~1.3분, 기획안 ~1.7분, codex 이미지 ~3분)에서 미룬 추정이다.

**키워드 점수.** `volume = PC + 모바일 월간 검색수`, `docs = 블로그 검색 총 문서 수`, `포화도 = docs / volume`. `config/blog.yaml`의 `min_volume`·`max_saturation`으로 거르고 `volume / (docs + 1)` 내림차순으로 정렬한다. 이미 쓴 키워드(`블로그/*/프로젝트.json`의 `keyword.main`)는 제외한다 — 자기 글끼리 경쟁하지 않게. 임계값은 초기 제안값이며 4주 운영 후 조정한다.

**근거 조사가 별도 단계인 이유.** 회차 재가공이 아니라 새 글이라 기댈 1차 자료가 없다. LLM이 기억으로 쓴 수치·날짜는 틀린다. `근거.json`의 각 항목은 `{claim, source_url, quote, checked_at}`이고, 본문은 **근거에 있는 주장만** 단정형으로 쓴다. 근거를 못 찾은 항목은 본문에 `[확인필요]`로 남고, 이 표식이 하나라도 있으면 lint가 게시를 막는다.

**연쇄 실행.** 게이트1 승인 뒤 ②~⑥은 `lib/blogPipeline.ts`가 요청과 분리된 비동기 루프로 순서대로 돌린다. 각 단계는 잡 러너의 잡 1개라 로그가 남는다. LLM 동시 실행은 1개로 제한한다(구독 CLI 한도). 서버가 중간에 죽으면 `상태.json`에 `running`이 남는데, 조회 시 해당 잡이 살아 있지 않으면 `interrupted`로 고쳐 표시하고 **그 단계부터 이어하기**를 제공한다.

## 4. 화면 설계

- 사이드바 `기획` 그룹에 **블로그 ✍️** `/blog` 추가 (`components/Nav.tsx` `items`에 한 줄).
- `/blog` — 탭 3개.
  - **글**: 상태별 목록(개요 대기·승인 대기·게시 대기·게시됨). 각 행에 키워드·상태·다음 행동 버튼.
  - **키워드**: 주차별 키워드 보드. 열 = 키워드 / 검색수(PC·모바일) / 문서 수 / 포화도 / 점수 / 상태(미사용·작성 중·게시됨). `이 키워드로 글 만들기`, `이번 주 N편 만들기`.
  - **성과**: 게시된 글 × 키워드 순위 추이(표 + 스파크라인). 100위 밖은 `-`.
- `/blog/[id]` — 왼쪽 단계 스테퍼, 가운데 편집, 오른쪽 미리보기·점검.

```text
블로그 › 에어프라이어 청소                상태: 원고 승인 대기
┌─────────┬──────────────────────────┬─────────────────────┐
│ ✓ 키워드 │ [개요] [근거] [본문] [이미지]│ 미리보기 (모바일 폭)   │
│ ✓ 개요   │                          │                     │
│ ✓ 근거   │  마크다운 편집기           │  네이버 본문 폭·서체에  │
│ ✓ 본문   │  (허용 문법만)            │  가깝게 렌더          │
│ ✓ 윤문   │                          ├─────────────────────┤
│ ✓ 이미지 │                          │ 점검  error 0 · warn 2│
│ ● 점검   │                          │ · 첫 문단에 키워드 없음 │
│ ○ 게시   │ [수정요청] [원고 승인]     │ · 이미지 alt 1개 비어있음│
└─────────┴──────────────────────────┴─────────────────────┘
```

- **근거 탭**은 주장-출처 표다. 행마다 출처 링크·인용문·`본문에서 사용됨` 표시. 사람이 행을 지우면 본문의 해당 문장이 `[확인필요]`로 바뀌어야 하므로, 삭제 시 "본문 재생성 필요" 배지를 띄운다.
- **게시 탭**: 모드 선택(6절), 광고 표기 선택, `복사 패키지 만들기` / `네이버에 임시저장`. 임시저장은 확인 다이얼로그 → `confirmed: true`.
- 승인 후 본문·이미지를 고치면 승인이 **자동 무효**가 된다(5절 sha256). 화면은 "승인 이후 변경됨 — 다시 승인 필요"를 표시한다.
- `/settings` 환경 점검에 네이버 키 5종 존재 여부, Playwright 설치, 네이버 로그인 프로필 상태를 추가한다.

## 5. 저장 구조와 데이터 계약

```text
블로그/<YYYYMMDD>-<슬러그>/
  프로젝트.json          메타 SSOT (아래)
  상위글.json            [{rank,title,description,link,bloggername,postdate}]
  개요.json              LLM 구조화 출력
  01-개요-승인.txt / 01-개요-수정요청.txt
  근거.json              [{id,claim,source_url,quote,checked_at}]
  본문.초안.md            윤문 전 원본
  본문.md                게시 대상
  이미지/00-대표.jpg, 01.jpg…  + 이미지.json [{n,file,alt,prompt,kind:'thumb'|'body'}]
  점검.json              {errors[],warnings[],checked_at,body_sha256}
  02-원고-승인.txt        내용 = 본문.md + 이미지 파일들의 sha256 목록
  게시패키지/본문.html · 본문.txt · 태그.txt
  게시결과.json           {mode,state,post_url,at,error}
  순위.json              [{date,keyword,rank|null}]
  상태.json  로그/
pipeline/data/blog/keywords/<YYYY-Www>.json
pipeline/config/blog.yaml · naver-editor.yaml
pipeline/prompts/blog/{outline,facts,draft,polish}.md
```

**`프로젝트.json`**

```json
{
  "id": "20260918-에어프라이어-청소", "version": 1, "revision": 4,
  "status": "review",
  "keyword": {"main": "에어프라이어 청소", "subs": ["에어프라이어 기름때"],
              "volume_pc": 0, "volume_mobile": 0, "docs": 0, "saturation": 0.0, "week": "2026-W38"},
  "intent": "방법형",
  "title": "", "title_candidates": [],
  "category": "", "tags": [],
  "disclosure": "none",
  "publish": {"mode": "copy", "post_url": null, "published_at": null},
  "createdAt": "", "updatedAt": ""
}
```

- `status`: `keyword → outline → facts → draft → images → review → ready → drafted → published`. `ready`는 게이트2 통과, `drafted`는 네이버 임시저장 완료, `published`는 사람이 발행 후 URL을 입력(또는 자동 감지)한 상태다.
- `disclosure`: `none | ad | sponsored | affiliate`. `none`이 아니면 본문 첫머리에 경제적 이해관계 문구를 넣고, 없으면 lint error다(`lintCarousel`의 광고 표기 규칙과 같은 취지).
- `개요.json` 스키마: `{title_candidates[3], intent, reader, sections[{h2, h3[], points[], keyword_use}], facts_needed[{id, question}], images[{n, kind, brief, alt}], faq[]}`.
- **본문.md 허용 문법**: `##`·`###`·문단·`**굵게**`·목록·인용·표·`![alt](이미지/NN.jpg)`·링크. 그 밖(HTML·코드펜스·`#` 1단 제목)은 lint error — 네이버 에디터에 붙였을 때 깨지지 않는 부분집합만 쓴다. 변환기는 `lib/blogRender.ts`에 직접 둔다(의존성 추가 없음).

**`config/blog.yaml`** — `blog_id`, `niche`(블로그 주제), `persona`(말투·1인칭 여부·독자), `seed_keywords[]`, `min_volume`, `max_saturation`, `weekly_target`, `length{min,max}`, `banned_phrases[]`, `max_posts_per_day: 1`, `min_hours_between_posts: 12`, `default_publish_mode: copy`.

**`lintBlog()` 규칙**

| 수준 | 규칙 |
|---|---|
| error | `[확인필요]` 잔존 / 허용 외 문법 / 광고 표기 누락 / 제목 비었음 / `banned_phrases` 포함(의료·금융 단정, "무조건·100%" 류) / 본문이 `length.min` 미만 / 이미지 파일 누락 / 기존 내 글과 5-gram 중복률 30% 초과 |
| warn | 제목·첫 문단에 주 키워드 없음 / 주 키워드 밀도 과다(제안 3% 초과) / 이미지 alt 비었음 / 이미지 3장 미만 / 외부 링크 5개 초과 / 소제목 3개 미만 |

수치는 초기 제안값이다. 네이버 검색 로직의 공식 기준이 아니다.

## 6. 게시 — 3단 모드

| 모드 | 동작 | 계정 위험 | 기본 |
|---|---|---|---|
| **copy** | `게시패키지/`에 서식 있는 HTML을 만들고, 화면의 `복사` 버튼이 클립보드에 `text/html`로 올린다. 사람이 네이버 에디터에 붙여넣고 이미지를 끌어다 놓는다 | 없음 | **기본값** |
| **draft** | Playwright가 **사용자가 직접 로그인해 둔 전용 크롬 프로필**로 에디터를 열어 제목·본문·이미지·태그를 채우고 **임시저장**까지만 한다. 발행 버튼은 사람이 누른다 | 있음 — 2절 약관상 자동화 게시에 해당할 수 있다 | 옵트인 |
| **publish** | 발행·예약 발행까지 자동 | 가장 큼 | **1차 범위에서 구현하지 않는다** |

draft 모드 규칙:

1. **비밀번호를 저장하지 않는다.** `python -m shortform blog login`이 headed 크롬을 띄우고 사람이 직접 로그인한다. 세션은 `pipeline/secrets/naver-profile/`에 남는다(이미 `.gitignore`·`safePath` 거부 대상). 캡차·2단계 인증도 사람이 푼다.
2. 항상 **headed**(창이 보이는 상태)로 돈다. 사람이 끼어들 수 있어야 한다.
3. 에디터 셀렉터·URL은 코드가 아니라 `config/naver-editor.yaml`에 둔다. 네이버가 DOM을 바꾸면 설정만 고친다. 에디터 진입 URL, iframe 구조, 붙여넣기 시 서식 보존 범위, 이미지 업로드 방식은 전부 **[미확인]** — 구현 첫 노드(B7)에서 임시저장 1건으로 실측한 뒤 확정한다.
4. 셀렉터가 하나라도 안 맞으면 **즉시 멈추고** 스크린샷을 `로그/`에 남긴다. 추측으로 다음 동작을 하지 않는다. copy 모드는 항상 살아 있는 폴백이다.
5. 멱등성: `pipeline/data/publishing.sqlite3`에 `blog_publishing(body_sha256, blog_id, state, post_url, updated_at, error)` + `UNIQUE(body_sha256, blog_id)`. 슬롯 선점 후 실행, 결과가 불확실하면 `unknown`으로 남기고 **자동 재시도 금지** — 사람이 네이버 임시저장함을 보고 `sync`한다. (`publishing.py`와 같은 상태머신)
6. 실행 전 검사: 게이트2 승인 파일의 sha256이 현재 본문·이미지와 일치 / lint error 0 / `max_posts_per_day`·`min_hours_between_posts` 통과 / `confirmed: true`.

## 7. 실행 구조와 API 계약

| 역할 | 위치 | 비고 |
|---|---|---|
| 프로젝트 CRUD·lint·md→html | Node `lib/blog.ts`, `blogTypes.ts`, `blogRender.ts` | 파일 직접 읽기·쓰기 |
| LLM 4단·연쇄 | Node `lib/blogPipeline.ts` → `runLlm` | `runLlm`에 `allowedTools?`·`maxTurns?` 추가(근거 조사용) |
| 네이버 API·게시기·순위 | Python `shortform/blog/{naver_api,keywords,serp,rank,naver_editor,publish}.py` | `playwright`는 `pyproject` extra `[blog]`, 지연 임포트 — `inspect`는 의존성 없이 계속 돈다 |
| CLI | `python -m shortform blog {keywords,serp,login,publish,sync,rank}` | `publish`는 `--execute` 없으면 검사만 |
| 읽기 브리지 | `inspect blog-keywords --week` | 키워드 JSON은 Python이 쓰므로 Python이 읽어 준다 |

| 메서드 · 경로 | 하는 일 |
|---|---|
| `GET/POST /api/blog` | 목록 / 키워드로 새 글 생성 |
| `GET/PUT /api/blog/[id]` | 조회 / 저장(`revision` 불일치 409) |
| `POST /api/blog/[id]/outline` | 상위글 분석 + 개요 생성 (`maxDuration = 600`) |
| `POST /api/blog/[id]/gate` | `{gate:'outline'|'body', action:'ok'|'fix', note?}` — 승인 파일 생성. `outline` 승인은 연쇄 시작 |
| `POST /api/blog/[id]/run` | `{from:'facts'|'draft'|'polish'|'images'|'lint'}` 그 단계부터 연쇄 (202 + 잡 id) |
| `POST /api/blog/[id]/package` | copy 모드 패키지 생성 |
| `GET /api/blog/keywords?week=` | 키워드 보드 |
| `POST /api/blog/batch` | `{count}` 상위 N개로 글 생성 + 개요까지 순차 실행 |
| `POST /api/jobs` 프리셋 추가 | `blog-keywords`, `blog-rank`, `blog-publish`(**dangerous**, `confirmed` 필수) |

환경 변수(키 이름만): `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`(오픈API 검색·데이터랩), `NAVER_AD_CUSTOMER_ID`, `NAVER_AD_ACCESS_LICENSE`, `NAVER_AD_SECRET_KEY`(검색광고 API, HMAC 서명). 기존대로 `pipeline/.env` → `loadDotEnv`가 자식 프로세스에 주입한다. 서명·키는 로그에 찍지 않는다.

**정기 실행.** 주간 키워드 발굴과 일일 순위 추적은 Windows 작업 스케줄러가 CLI를 직접 부른다(`blog keywords`, `blog rank`). 콘솔이 꺼져 있어도 돈다. 글 생성 배치는 LLM 비용·한도가 걸리므로 자동 예약하지 않고 화면의 `이번 주 N편 만들기`로 사람이 시작한다.

## 9. 구현 수용 기준

1. 네이버 키 없이도 `/blog`가 열리고, 키워드를 손으로 입력해 개요→본문→패키지까지 만들 수 있다(키는 발굴·순위에만 필요).
2. `[확인필요]`가 남은 원고는 어떤 모드로도 게시 단계에 들어가지 못한다.
3. 원고 승인 후 본문을 한 글자라도 바꾸면 게시가 거부되고 재승인을 요구한다.
4. `confirmed` 없는 `blog-publish` 요청은 러너에서 거부된다. 같은 본문을 두 번 임시저장하지 않는다.
5. 에디터 셀렉터를 일부러 틀리게 넣으면 게시기가 아무것도 입력하지 않고 스크린샷만 남기고 멈춘다.
6. 비밀번호·쿠키·API 서명이 로그·잡 JSON·`게시결과.json` 어디에도 남지 않는다.
7. copy 패키지를 네이버 에디터에 붙였을 때 소제목·굵게·목록·표가 유지된다(사람 확인 1회).
8. 기존 CLI·회차·카드뉴스 동작에 변화가 없다(`python -m shortform inspect list` 회귀 확인).

## 10. 넘지 않는 선

- **발행은 사람이 한다.** 자동화는 임시저장까지. 하루 1편 상한은 설정으로도 3편을 넘기지 못하게 코드에 박는다.
- **상위 글을 베끼지 않는다.** 분석 입력은 API가 주는 제목·요약까지다. 남의 본문을 긁어 재작성하지 않는다.
- **근거 없는 단정을 쓰지 않는다.** 수치·날짜·효능은 `근거.json`에 출처가 있어야 한다.
- **경제적 이해관계는 글 첫머리에 밝힌다**(공정위 추천·보증 심사지침 취지). 세부 문구 요건은 **[미확인]** — 협찬 글을 실제로 쓰기 전에 확인한다.
- AI 생성 글에 대한 네이버의 검색 노출 기준은 공개된 공식 문서를 확인하지 못했다 **[미확인]**. 대량·유사 문서가 제재 사유였다는 것(2절)만 확실하므로 편수보다 글당 품질에 맞춘다.

## 11. 정해야 할 것

1. **블로그 주제(niche)와 말투.** 키워드 시드·프롬프트·금칙어가 전부 여기서 나온다. `config/blog.yaml`을 채워야 B3·B4를 시작할 수 있다.
2. **draft 모드를 쓸지.** 약관 위험을 감수할지는 계정 주인의 판단이다. 안 쓰면 B6·B7이 copy 패키지만 남고 크게 줄어든다.
3. 검색광고 API는 광고주 계정 가입이 필요하다(광고 집행은 불필요 **[미확인]**). 계정이 없으면 키워드 검색수를 손으로 넣는 폴백으로 시작한다.
4. 윤문 단계에 `vendor/im-not-ai`의 `verify_gates.py`(변경률 게이트)를 붙일지 — 저장소 밖 경로 의존이라 1차에서는 프롬프트 윤문만 한다.

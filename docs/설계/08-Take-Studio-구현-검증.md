# Take Studio 첫 구현 및 검증

작성일: 2026-09-23. 기준 설계: [07-Take-Studio-UIUX-설계.md](07-Take-Studio-UIUX-설계.md).

## 실행 및 사용

`pipeline`에서 `npm run dev -w web`을 실행하고 `http://127.0.0.1:3123/studio`로 접속한다. 운영 빌드는 `npm run build -w web`, 실행은 `npm run start -w web -- --hostname 127.0.0.1`이다.

1. 빈 프로젝트 또는 기존 A/B 회차로 프로젝트를 만든다. 가져오기는 원본을 별도 복사한다.
2. 브리프와 컷별 프롬프트를 저장한다. 이미지·영상·오디오를 소재함에 업로드한다.
3. 캔버스에서 이미지 노드를 컷에 연결하거나 오른쪽 참조 목록에서 선택한다. 기획을 검토한 뒤 승인한다.
4. 이미지/영상 생성 버튼에서 모델과 설정 기준 비용을 확인하고 실행한다. 업로드한 소재를 테이크로 추가할 수도 있다.
5. 두 테이크를 비교하고 사용할 결과를 선택한다. 새 결과가 기존 선택을 자동으로 바꾸지 않는다.
6. 편집에서 컷 순서·길이·원본 시작점·자막·비율·오디오를 조정하고 미리보기로 확인한다. 나레이션 대본을 저장하면 Qwen 음성 생성도 실행할 수 있다.
7. 검수·내보내기에서 MP4를 출력한다. 아카이브 포함을 선택한 출력본만 다음 기존 아카이브 업로드 명령에 포함된다.

실행 환경은 기존 Python 가상환경, Node, FFmpeg/ffprobe를 사용한다. 이미지 생성에는 로그인된 Codex CLI, 영상 생성에는 `FAL_KEY`, 나레이션 생성에는 `/voices`에서 시작한 Qwen 로컬 음성 서비스가 필요하다. 인증키는 브라우저에 전달하지 않는다.

## 구현 범위

| 영역 | 구현 내용 |
|---|---|
| 프로젝트 | 생성, 기존 A/B 회차 가져오기, 브리프, 단계 전환, 파일 영속 저장 |
| 캔버스 | React Flow, 참조 연결, 위치 저장, 줌·미니맵, 스토리보드 전환 |
| 컷·테이크 | 컷 추가·순서 변경, 이미지/영상 생성, 기존 소재 추가, 복수 후보 보존, 2개 비교·선택 |
| 디렉터 기본 | 컷별 프롬프트·카메라·스타일 텍스트, 참조 이미지 선택 |
| 편집 | 이미지·영상 혼합, 길이·트림 시작점, 자막, 9:16/16:9/1:1, 전체 오디오, 공유 Remotion 미리보기 |
| 음성 | 대본 편집, 자막에서 대본 가져오기, Qwen 한국어 Sohee 생성, 결과를 소재함에서 선택 |
| 출력 | 선택본 snapshot, 실행별 독립 public 디렉터리, 버전별 MP4, 다운로드, 아카이브 포함 선택 |
| 실행 안전성 | 원자 저장, 프로세스 파일 잠금, revision 충돌, 실행 fingerprint·idempotency key, 엔진 종류별 동시 실행 1개 |
| 복구 | 작업 의도 선저장, 원격 요청 ID 저장, 프로세스 종료 감지, unknown 상태 조회, 확인 없는 유료 재요청 금지 |

이미지 참조는 최대 8개, 현재 fal 이미지→영상 모델은 시작 이미지 1개만 지원한다. 영상 길이는 실제 `config/fal.yaml`의 생성 길이를 넘을 수 없다. 100MB 업로드, 200MB 로컬 가져오기, 프로젝트당 60컷을 지원한다. 생성 비용은 설정값 기준 추정이며 미확인 비용은 무료로 표시하지 않는다.

## 저장 계약과 설계 구체화

- 프로젝트와 복사한 소재는 `pipeline/data/studio/projects/<id>/`에 저장한다. 기존 회차 안의 `.studio` 대신 별도 저장소를 사용해 원본을 보존하고 실행 경계를 단순화했다. 생성 데이터는 Git에서 제외했다.
- 프로젝트는 `project.json`, 후보는 독립 asset과 take, 출력은 입력 snapshot을 가진 export로 저장한다. 영상 렌더링은 기존 렌더의 공유 `public/ep`를 사용하지 않는다.
- 프롬프트·스타일·카메라·참조·화면 비율이 변경되면 관련 테이크를 재검수한다. 자막·길이·배치 변경으로 영상 생성을 불필요하게 무효화하지 않는다. 나레이션 대본 변경도 음성 재검수 대상으로 표시한다.
- 편집 폼은 편집을 시작한 revision을 보관한다. 백그라운드 갱신으로 이를 바꾸지 않으며 충돌 시 작성한 내용을 유지하고 최신 내용을 다시 불러올 수 있다.
- API는 `/api/studio`, `/api/studio/:id`, `/api/studio/:id/assets`로 통합했다. 요청은 고정된 작업 종류에만 매핑한다. 작업 상태는 5초 polling, 상세 로그·프로세스 취소는 기존 `/jobs`를 사용한다.
- 이 릴리스의 그래프는 이미지 참조→컷의 제한된 그래프다. 임의 실행 노드 연결이나 순환을 허용하지 않는다. 씬 그룹·다중 의존성 실행 DAG는 후속 확장이다.
- 제작 API는 localhost/127.0.0.1 및 동일 Origin에서만 허용한다. 기존 Cloudflare/R2 아카이브는 조회·재생 역할을 유지한다.
- 아카이브에는 명시적으로 포함한 완성 영상만 추가한다. 프롬프트, 프로젝트 JSON, 미선택 원본·참조는 올리지 않는다.

## 검증 결과

- Python 테스트 **73개 통과**: studio, archive, inspect, r2, planfile_a. 별도 기존 TTS 서비스 테스트는 현재 가상환경의 선택 의존성 조건 때문에 skip되었다.
- 신규 테스트: 한글 프로젝트, 원본 복사 보존, 프로세스 간 저장 충돌, 경로/파일 내용 검증, 입력 변경·명시적 재검수, 중복 제출, 유료 접수 응답 손실, 원격 ID 보존, 종료된 프로세스 복구, 공급자 동시 실행 제한, 음성 생성·대본 변경 검수, 아카이브 선택.
- TypeScript 검사 통과. Next.js 16.3.4 프로덕션 빌드 통과. 기존 동적 파일 접근 tracing 경고 8개는 남아 있다.
- 실제 API로 PNG 2개·MP4·WAV 업로드 → 2개 이미지 테이크 중 하나 선택 → 영상 컷 추가 → 트림·한글 자막·오디오 → Remotion MP4 출력 성공.
- 출력 확인: 1080×1920 H.264 + AAC, 약 1.045초. 첫 프레임에서 한글 자막이 정상 표시되는 것을 확인했다. 다운로드 Range 요청은 206 및 요청한 100바이트를 반환했다.
- 기존 A안 `2026-09-13 / A-01` 회차에서 5컷·소재 13개·선택 테이크 5개 가져오기 성공.
- `/studio`, `/api/studio`, `/api/episodes` HTTP 200, 다른 Origin의 변경 요청은 403.
- 유료 Codex/fal 요청과 실제 GPU 음성 생성은 실행하지 않았다. 어댑터·상태 복구는 모의 응답으로 검증했다.
- Chrome 자동화 도구의 탐색/디버거 연결이 반복해서 실패했다. 실제 화면 클릭, 좁은 화면·200% 확대, 100노드 성능 측정은 이번 세션에서 완료하지 못했다. 빌드와 HTTP 검증을 브라우저 검증으로 간주하지 않는다.

## 다음 확장

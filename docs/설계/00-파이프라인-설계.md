# 숏폼 자동화 파이프라인 설계

작성일: 2026-09-08
상태: 승인됨 (2026-09-08). B 트랙 주제는 엔터로 확정. 채널 운영 결정은 `01-B트랙-운영전략.md`를 따른다.

## 1. 목표

레퍼런스 발굴부터 유튜브 쇼츠 업로드까지를 한 파이프라인으로 묶는다. 트랙은 둘이다.

| 트랙 | 소재 | 주제 | 자동화 수준 |
|---|---|---|---|
| B (주) | 방송 클립의 원음 대사 + 자막·AI 댓글 오버레이, 선택적 TTS | 한 예능 중심에서 같은 감정의 인접 소재로 확장 | 제작 컨펌 2회 + 업로드 승인 1회 외 자동 |
| A (별도) | Codex 이미지 → fal.ai MiniMax H3 영상 | 동물 일상물 또는 애니 캐릭터 요리 힐링물 | 게이트 기반 반자동 |

첫 플랫폼은 유튜브 쇼츠. 인스타·틱톡은 범위 밖이다.

첫 마일스톤: B 트랙 1편을 제작 컨펌 2회와 업로드 승인 1회를 거쳐 유튜브에 올린다. A 트랙은 그 뒤 캐릭터 시트 템플릿부터 시작한다.

## 2. 절대 규칙

1. **기획 컨펌 없이 이미지·소재를 만들지 않는다.**
2. **이미지 컨펌 없이 영상을 만들지 않는다.**
3. **업로드 승인 없이 업로드하지 않는다.**
4. 모든 산출물은 `숏폼/YYYY-MM-DD/` 날짜 폴더 안에만 만든다. 파이프라인 코드는 `숏폼/pipeline/`에 둔다.

컨펌은 승인 파일의 존재로 판정한다. 파이프라인은 승인 파일이 없으면 해당 단계에서 멈추고 무엇을 확인해야 하는지 출력한 뒤 종료한다.

## 3. 폴더 규칙

하루에 여러 편을 만들 수 있으므로 날짜 폴더 아래 편(에피소드) 폴더를 둔다.

```
숏폼/
├─ pipeline/                       파이프라인 코드 (트랙 공통)
├─ 2026-09-08/
│  ├─ 00-파이프라인-설계.md         이 문서 (첫날만)
│  ├─ B-01-혈압낮추는습관/          B 트랙 1편
│  │  ├─ 01-기획안.md
│  │  ├─ 01-기획-승인.txt           ← 사용자가 만든다
│  │  ├─ 02-이미지/
│  │  │  ├─ 컨택트시트.png          선택된 스톡 클립 썸네일 모음
│  │  │  └─ 클립목록.json
│  │  ├─ 02-이미지-승인.txt         ← 사용자가 만든다
│  │  ├─ 03-소재/                   다운받은 스톡 mp4, tts.mp3, 자막 타이밍
│  │  ├─ 04-영상/final.mp4
│  │  ├─ 04-업로드-승인.txt         ← 사용자가 만든다
│  │  └─ 05-업로드결과.json
│  └─ A-01-부엉이아침/              A 트랙 1편
│     ├─ 01-기획안.md               컷표 + 락 블록 4개
│     ├─ 01-기획-승인.txt
│     ├─ 02-이미지/
│     │  ├─ 캐릭터시트.png          3면 + 표정 + 의상변형 + 디테일
│     │  ├─ 키프레임/1A.png ...
│     │  └─ 컨택트시트.png          check_frames.py 출력
│     ├─ 02-이미지-승인.txt
│     ├─ 03-소재/클립/1A.mp4 ...    H3 결과
│     ├─ 04-영상/final.mp4
│     ├─ 04-업로드-승인.txt
│     └─ 05-업로드결과.json
```

승인 파일은 내용이 비어 있어도 된다. 수정 요청은 승인 파일 대신 `01-기획-수정요청.txt`에 적으면 파이프라인이 읽어서 다시 만든다.

## 4. 공통 단계

### 4.1 발굴 (discover)
- 입력: 주제 키워드 목록 (`pipeline/config/keywords.yaml`)
- 도구: YouTube Data API v3. 세 갈래를 모두 돈다.
  1. **인급동**: `videos.list(chart=mostPopular, regionCode=KR, videoCategoryId=24|23|1)` — 엔터·코미디·영화/애니 카테고리.
  2. **조회수 상위**: `search.list(q=키워드, order=viewCount, publishedAfter=최근 90일)`.
  3. **재사용 허용**: `search.list(q=키워드, videoLicense=creativeCommon)` — CC BY 후보. 화면 소재로 쓸지는 클립 컨펌에서 사람이 판정한다.
- 출력: `pipeline/data/references.jsonl`에 영상 ID·제목·조회수·채널·라이선스·수집 경로·수집일 누적. 이미 있는 ID는 건너뛴다.
- 발굴 결과는 **주제와 대본 구조를 배우는 용도**다. 영상 파일 자체를 화면에 쓰는 것은 4.4에서 따로 판정한다.
- 인스타 레퍼런스는 쏘티AI로 사용자가 URL을 모아 `pipeline/data/manual-refs.txt`에 넣으면 같은 흐름으로 처리한다.

### 4.2 전사 (transcribe)
- 도구: yt-dlp로 음성만 받고 faster-whisper로 전사. 단어 단위 타임스탬프 저장.
- 출력: `pipeline/data/transcripts/<id>.json`
- 전사한 원본 영상 파일은 보관하지 않는다. 대본 구조 학습 외에 재사용하지 않는다.

### 4.3 기획 (plan)
- 도구: Claude API
- 입력: 상위 레퍼런스 대본 3~5개, 채널 주제, 트랙
- 출력: `01-기획안.md`. 내용은 트랙별로 다르다 (5절, 6절).
- 여기서 멈추고 `01-기획-승인.txt`를 기다린다.

### 4.4 이미지 (images)
- 트랙별로 다르다. 공통점은 결과를 `02-이미지/컨택트시트.png` 한 장으로 요약해 사용자가 한눈에 볼 수 있게 하는 것.
- 여기서 멈추고 `02-이미지-승인.txt`를 기다린다.

### 4.5 소재 (assets)
- 트랙별로 다르다 (5절, 6절).

### 4.6 렌더 (render)
- 도구: Remotion. 1080x1920, 30fps. `브리핑 포커스`는 35~60초 지침, 두 피드 카드 템플릿은 15~30초를 강제한다.
- 컴포지션 구성: 배경 클립 레이어, 자막 레이어(단어 단위 하이라이트), 댓글 카드 레이어, BGM.
- 댓글 카드: `브리핑 포커스`는 기획안의 댓글 JSON을 읽어 지정 시각에 화면 하단에서 올라온다. 두 피드 카드 템플릿은 첫 댓글을 0초부터 고정 표시하고, 이후 댓글은 지정 시각에 교체한다. 프로필은 색상 원 + 이니셜, 닉네임은 생성 규칙상 실존 계정을 흉내 내지 않는다.
- 하드컷만 쓴다. 전환효과 없음.
- 출력: `04-영상/final.mp4`, 썸네일 `04-영상/thumb.jpg`

### 4.7 업로드 (upload)
- 도구: YouTube Data API v3 `videos.insert`. 최초 1회 OAuth 후 리프레시 토큰을 `pipeline/secrets/`에 저장. 이 폴더는 공유하지 않는다.
- 제목·설명·태그는 기획안 메타데이터 절에서 읽는다. 기본 공개 상태는 기획안에 적힌 값을 따르고 없으면 `unlisted`.
- `04-업로드-승인.txt`가 있어야 실행한다.
- 출력: `05-업로드결과.json` (video ID, URL, 시각)
- 할당량: 기본 10,000 단위/일, 업로드 1건 약 1,600 단위. 하루 6건 이하로 제한한다.

## 5. B 트랙 세부

B 트랙의 소재 비율, 포맷, TTS 예외 사용, 오디오 후처리와 확장 기준은
`01-B트랙-운영전략.md`(같은 폴더)를 기준으로 한다.

> **구현 상태:** 원음 중심 B 트랙은 승인된 목표 사양이며 아직 코드에는 반영되지 않았다. 현재 코드는 TTS 중심이다. 선택적 TTS, 최종 타임라인 길이 검사, 원본 오디오 유지·BGM 덕킹, 노이즈 감소·음량 정규화, 무TTS 렌더 테스트를 구현해야 한다.

### 5.1 기획안 형식
```
# 템플릿
화이트 피드 카드

# 제목 후보 3개
# 훅 (첫 1~2초, 한 문장)
# 대사·자막 구성 (원음 구간, 강조 자막, 선택적 TTS 문장, 소재 출처 태그)
# AI 댓글 6개 (닉네임, 내용, 등장 시각 초)
# 메타데이터 (설명, 태그, 공개 상태, 출처 표기)
# 참고한 레퍼런스 (영상 ID, 배운 구조 한 줄)
```
템플릿 절을 생략하면 `브리핑 포커스`다. 이름은 위 한글 표시명을 정확히 사용한다.
`화이트 피드 카드`와 `블랙 피드 카드`는 최종 편집 타임라인이 15~30초(경계 포함)인지 검사한다.
TTS는 선택 사항이며 원본 대사만으로 이해되는 영상에는 넣지 않는다.
기획은 레퍼런스의 구조만 따르고 제목·맥락·강조 자막은 새로 쓴다. 소재 출처 태그는 `clip` / `stock` 둘 중 하나다.

### 5.2 클립 단계
소재 태그별로 다른 곳에서 후보를 모으고, 결과는 컨택트시트 한 장으로 합친다.

| 태그 | 출처 | 라이선스 | 비고 |
|---|---|---|---|
| `clip` | yt-dlp로 유튜브 검색 (방송사 공식 채널·예고편) | 저작권 유효 — Content ID 클레임 가능 | 기본값. 이지컷 방식 |
| `stock` | Pexels Video API | Pexels 라이선스 (상업 이용·수정 허용, 출처 표기 불요) | 추상적인 문장의 배경용 |

- 문장별 검색어로 후보 4개씩. `clip`은 채널명에 방송사가 들어간 후보를 앞으로 정렬해 기본 선택이 공식 채널이 되게 한다. 판별은 채널명 부분 일치라서 무단 재업로드도 걸린다 — 최종 판정은 사람이 한다.
- **컨택트시트에는 유튜브 썸네일이 아니라 실제로 쓰일 지점의 프레임을 넣는다.** 썸네일은 문구가 박힌 홍보 이미지라 화면에 깔릴 장면과 다르다. 영상을 통째로 받지 않고 스트림 URL에 seek해서 한 장만 뽑는다.
- 발췌 시작 지점은 영상 길이의 25%를 기본값으로 하고 `클립목록.json`의 `start`에 적는다. 문장과 안 맞으면 이 값을 고치거나 후보를 바꾼다.
- 공식 채널은 초록 테두리, 아니면 빨간 테두리로 구분한다.
- 사용자는 컨택트시트를 보고 승인하거나 `02-이미지-수정요청.txt`에 "3번 문장 다른 걸로" 식으로 적는다.

**화면비**: 방송 클립은 전부 16:9다. 9:16으로 그냥 자르면 화면 폭의 70%가 날아가 인물이 잘린다. 원본을 통째로 가운데 두고 위아래를 같은 화면의 흐린 확대본으로 채운다.
자동 소재는 회전 메타데이터를 반영한 원본 화면비를 타임라인에 기록한다. 수동 클립은
`클립목록.json` 항목의 `media_layout`에 `portrait` 또는 `landscape`를 적으며, 생략 시
기존 동작과 같은 `landscape`다.

**저작권 규칙** (2026-09-08 사용자 결정으로 개정):
- 주력 장면은 방송 클립을 인용하고, 맥락 연결에 필요할 때만 라이선스가 확인된 스톡 영상을 보조 화면으로 쓴다. 사용자는 Content ID 클레임 가능성과 수익화 불리함을 확인한 뒤 이지컷 방식을 택했다.
- Content ID 처리 결과는 권리자 설정에 따라 수익 귀속, 추적 또는 차단으로 달라질 수 있고, 별도의 저작권 삭제 요청도 가능하다. 특정 결과를 전제로 운영하지 않는다.
- B 트랙은 원음 중심이라 내레이션 중심 편집보다 독창성 판단에 불리할 수 있다. TTS 유무와 별개로 제목, 장면 선택, 맥락 구성, 자막과 비평에서 채널 고유의 가치를 분명히 만든다.
- 설명란에 인용한 영상의 제목·채널·URL과 인용 고지를 자동으로 넣는다.
- **Content ID 회피 목적의 화면 변형(반전·크롭·속도 조절)은 하지 않는다.** 인용이 아니라 우회이기 때문이다.

## 6. A 트랙 세부

기존 shortform 스킬의 게이트 3개를 이 파이프라인의 컨펌 구조에 맞춘다.

| shortform 스킬 | 이 파이프라인 |
|---|---|
| 게이트 1 컷 분해 승인 | `01-기획-승인.txt` |
| 게이트 2 시트 승인 + 게이트 3 키프레임 검사 | `02-이미지-승인.txt` (시트와 키프레임을 한 번에 확인) |

### 6.1 기획안 형식
```
# 시놉시스
# 락 블록 4개 (CHARACTER / COSTUME / GLOBAL STYLE / NEGATIVE)
# 컷표 (컷 번호, TC, 렌즈, 액션, 필수/선택)
# 음향 설계 (환경음, 효과음, 무음 구간)
# 메타데이터
```

### 6.2 이미지 단계
1. **캐릭터 시트**: 레퍼런스 폴더의 부엉이 시트 구성을 따른다. 한 장에 3면 턴어라운드, 표정 4~6개, 의상·소품 변형, 디테일 클로즈업. Codex CLI 브리지로 락 블록을 넣어 생성한다. 마음에 들 때까지 이 한 장만 반복한다.
2. **키프레임**: 컷마다 같은 시트를 참조 이미지로 첨부해 Codex로 생성. 앞 컷 결과를 참조하지 않는다.
3. **검사**: `check_frames.py`로 비율 9:16, 세로 1280px 이상, 필수 컷 누락, 워터마크 의심을 자동 판정하고 컨택트시트를 만든다.
4. 사용자는 시트와 컨택트시트를 보고 승인한다. 좌우 일관성은 사람이 본다.

Codex 이미지 생성은 ChatGPT 구독 쿼터를 텍스트보다 3~5배 빨리 쓴다. 한 편에 시트 3~5회 + 키프레임 8~12장 정도로 잡는다.

### 6.3 소재 단계
- fal.ai MiniMax H3. 컷마다 키프레임 + 캐릭터 시트를 reference-to-video에 넣고 컷표의 ACTION·CAMERA를 모션 프롬프트로 준다. 외모·의상·스타일은 다시 쓰지 않는다.
- 컷당 5초, 768p 기본. 필요한 컷만 2K.
- 비용 상한: 편당 10달러. 넘으면 멈추고 알린다.
- 실패 컷은 `03-소재/실패.txt`에 적고 사용자가 힉스필드나 NewTake 웹 UI에서 수동으로 만들어 같은 이름으로 넣으면 이어서 진행한다.

### 6.4 렌더 차이
- 자막은 대사가 없으면 생략. 음향 설계(환경음, 효과음, 클라이맥스 뒤 0.5초 무음)를 Remotion 오디오 트랙으로 넣는다.
- 댓글 카드는 A 트랙에서도 쓴다. 힐링물이므로 톤은 감탄·공감형으로 기획안에서 생성한다.

## 8. 실행 방식

- 명령 하나로 편 단위 실행: `pipeline run --track B --date 2026-09-08 --episode 01`
- 승인 파일이 없으면 해당 단계에서 멈추고 종료 코드 2. 승인 후 같은 명령을 다시 실행하면 이어서 간다.
- 상태는 편 폴더의 `상태.json`에 기록해 재실행 시 끝난 단계를 건너뛴다.
- 스케줄은 첫 마일스톤 이후에 붙인다. 수동 실행으로 3편 이상 성공한 뒤 Windows 작업 스케줄러에 등록한다.

## 9. 오류 처리

- 외부 API 실패는 3회 재시도 후 `상태.json`에 오류를 적고 종료한다. 부분 산출물은 지우지 않는다.
- 스톡 검색 결과가 0건인 문장은 검색어를 Claude가 다시 만들어 1회 재시도하고, 그래도 없으면 컨택트시트에 빈 칸으로 표시해 사용자가 고르게 한다.
- 업로드는 재시도하지 않는다. 실패하면 사용자에게 알리고 `05-업로드결과.json`에 오류를 남긴다. 중복 업로드를 막기 위해서다.

## 10. 검증 기준

- B 트랙: 승인 파일 3개만 만들어 주면 나머지가 자동으로 돌아 유튜브에 unlisted 영상이 올라간다.
- A 트랙: 시트 1장 + 키프레임 6장으로 30초 영상이 나오고 얼굴이 컷 사이에서 유지된다.

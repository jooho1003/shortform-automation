# Take Studio UI/UX 설계 계획

작성: 2026-09-23 · 범위: 레퍼런스 조사, 설계, 검토용 HTML 시안. 앱 구현·과금 생성·운영 배포는 포함하지 않는다.

1. Newtake 홈, 사용자가 지정한 제작 캔버스, 디렉터 스튜디오의 실제 화면을 관찰한다.
2. 현재 로컬 제작 콘솔 및 원격 아카이브의 역할과 구현 재사용 범위를 확인한다.
3. 프로젝트 → 씬 → 컷 → 테이크 구조, 노드 캔버스, 제작 단계 전환, 실행·버전 관리 계약을 설계한다.
4. 기능 대응표와 구현 순서, 클릭 가능한 독립 HTML 시안을 작성한다.
5. 시안의 주요 전환을 확인하고 관찰 사실과 제안을 구분하여 검토한다.

G1 완전성 PASS · G2 하드 오버라이드 PASS · G3 클램프 PASS · G4 PASS · G5 PASS.
설계·모호한 요구 해석·최종 리뷰는 메인이 직접 수행하며 powerful 비율 초과 근거에 해당한다.
사용자 기존 파일과 앱 코드를 수정하지 않는다. 생성 크레딧 사용이나 타사 프로젝트 복사는 수행하지 않는다.

## 완료 및 검증

- Newtake 홈·읽기 전용 제작 캔버스·디렉터 스튜디오/촬영 패널을 직접 확인했다.
- 기존 구현을 기준으로 기능 대응표, 상태·테이크·실행 계약, 파일 이전, 원격 운영 경계와 S0~S5 구현 순서를 작성했다.
- 독립 HTML 시안에 홈, 6개 제작 단계, 컷 선택, 캔버스/스토리보드 전환, 테이크 비교·선택, 입력 변경 안내를 구성했다.
- JavaScript 문법·계획 JSON 파싱·정적 ID 중복 검사 통과. 외부 이미지/스크립트 의존 없음.
- 로컬 HTTP 200 및 UTF-8 응답 내용 일치를 확인했다.
- Chrome 제어 시간 초과로 시안의 브라우저 상호작용·시각 검증은 완료하지 못했다.
- 앱 코드·운영 배포·타사 프로젝트·크레딧은 변경하지 않았다. 기존 미추적 session-notes 및 별도로 나타난 sh.exe.stackdump는 보존했다.
- 결과는 로컬 설계 파일로 남겼으며 커밋/푸시는 하지 않았다.
